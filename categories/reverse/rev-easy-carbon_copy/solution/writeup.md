# Копирка

| Событие | Название | Категория | Сложность |
| :-----: | :------: | :-------: | :-------: |
| VKACTF Kids 2026 | Копирка | Reverse | Easy |

**Обращение перестановки и колеса замен**

### Описание

Восстановите последнюю запись школьного принтера по следу, оставшемуся на копирке.

### Решение

В выдаче находятся Linux x86-64 программа [carbon](../give/carbon) и файл [last.spool](../give/last.spool). Запускаем `carbon --help`: программа принимает флаг первым аргументом, а путь к данным — необязательным вторым. По умолчанию она ищет `last.spool` рядом с собой.

Для анализа используем REA с GNU objdump. В текущем ELF начало основной функции находится по адресу `0x1280`. Проверка сигнатуры файла видна по адресу `0x13f5`, построение таблицы замен — в районе `0x1589`, а цикл проверки ввода — `0x1601–0x169e`. Адреса здесь относительные виртуальные адреса ELF до загрузочного смещения ASLR. Дальнейший Python-код — восстановленный алгоритм, а не исходник программы.

Сначала разбираем заголовок. Все многобайтовые числа записаны в little-endian:

| Смещение | Размер | Содержимое |
| :--- | :--- | :--- |
| `0x00` | 4 | Сигнатура `CCP2` |
| `0x04` | 1 | Версия: `1` |
| `0x05` | 1 | Длина ввода `n`: `37` |
| `0x06` | 1 | Шаг перестановки `step`: `7` |
| `0x07` | 1 | Начальное смещение `offset`: `11` |
| `0x08` | 4 | Начальное состояние генератора: `3266815257` |
| `0x0c` | 4 | Начальное значение `carry`: `99` |
| `0x10` | `n` | Преобразованные байты |

Программа читает ввод в порядке `pos = (offset + step*k) % n`. Так как `gcd(7, 37) = 1`, за 37 шагов она посещает все позиции ровно один раз. Значит, восстановленные символы нужно раскладывать по этим индексам.

В коде дважды встречается цепочка сдвигов на `13`, `17` и `5`: это xorshift32. Перенесём её в Python с сохранением 32-битного переполнения:

```python
def xs(x):
    x ^= (x << 13) & 0xffffffff
    x ^= x >> 17
    return (x ^ (x << 5)) & 0xffffffff
```

Перед проверкой строится `wheel`, перестановка байтов `0..255`. Для перемешивания используется отдельное состояние `seed ^ 0x70617072` и алгоритм Фишера — Йетса:

```python
wheel = list(range(256))
wheel_seed = seed ^ 0x70617072
for i in range(255, 0, -1):
    wheel_seed = xs(wheel_seed)
    j = wheel_seed % (i + 1)
    wheel[i], wheel[j] = wheel[j], wheel[i]
```

В основном цикле очередной символ `x = flag[pos]` преобразуется так:

```python
seed = xs(seed)
r = k % 7 + 1
z = wheel[(x + carry + 13*k) & 255]
y = rol8(z, r) ^ (seed & 255)
```

Полученный `y` сравнивается с байтом из `last.spool`. После этого программа меняет колесо и перенос:

```python
u, v = (carry + k) & 255, (y + x) & 255
wheel[u], wheel[v] = wheel[v], wheel[u]
carry = (y + x + 7*k) & 255
```

Именно поэтому нельзя один раз построить обратную таблицу и независимо расшифровать все символы: состояние зависит от уже обработанных байтов.

Обращаем операции в обратном порядке: снимаем XOR с потоком генератора, вращаем вправо, ищем значение в текущем колесе и вычитаем перенос с добавкой `13*k`. После восстановления символа обновляем состояние так же, как программа:

```python
flag = bytearray(n)
for k, y in enumerate(data[16:]):
    seed = xs(seed)
    z = y ^ (seed & 255)
    r = k % 7 + 1
    z = ((z >> r) | (z << (8-r))) & 255
    x = (wheel.index(z) - carry - 13*k) & 255
    flag[(offset + step*k) % n] = x
    u, v = (carry + k) & 255, (y + x) & 255
    wheel[u], wheel[v] = wheel[v], wheel[u]
    carry = (y + x + 7*k) & 255
```

