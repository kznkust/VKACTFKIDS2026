# Палимпсест

| Событие | Название | Категория | Сложность |
| :-----: | :------: | :-------: | :-------: |
| VKACTF Kids 2026 | Палимпсест | Reverse | Hard |

**Разбор страничной VM и обращение раундов**

### Описание

Восстановите первую надпись в тетради, где каждое исправление оставило свой след.

### Решение

В выдаче лежат Windows x86-64 программа [palimpsest.exe](../give/palimpsest.exe), файл [classroom.palm](../give/classroom.palm) и [библиотечная карточка](./give/bookplate.txt). Карточка намекает на перестановку страниц, меняющееся значение значков и 32-битную арифметику.

Открываем именно выданный EXE через REA. Дизассемблирование GNU objdump и декомпиляция IDA через REA приводят к функции `sub_140011BA0`. Загрузка страниц находится в районе `0x140011dd8`, декодер — `0x140011e4e`, разбор команд — `0x140011f21`, а диспетчер VM — `0x1400120d8`. Это адреса при предпочтительной базе PE `0x140000000`.

Программа принимает `[flag [asset_file]]`, требует флаг длиной 32 байта и проверяет его после исполнения собственной виртуальной машины. Сравниваются восемь 32-битных слов. Поэтому сначала восстановим байткод и его смысл, затем обратим преобразование.

Первые 24 байта `classroom.palm` разбираются форматом `<4sBBBBIIII`, все числа little-endian:

| Смещение | Размер | Содержимое |
| :--- | :--- | :--- |
| `0x00` | 4 | Сигнатура `PLM3` |
| `0x04` | 1 | Версия `1` |
| `0x05` | 1 | Число регистров: `16` |
| `0x06` | 1 | Вместимость страницы: `16` команд |
| `0x07` | 1 | Число страниц: `48` |
| `0x08` | 4 | Число команд: `754` |
| `0x0c` | 4 | Первая физическая страница: `26` |
| `0x10` | 4 | Начальные чернила `ink`: `1908843021` |
| `0x14` | 4 | Соль финального состояния: `2262714803` |

Следующие 64 байта — четыре таблицы по 16 кодов операций. Страницы начинаются со смещения `88`, каждая занимает `144` байта: заголовок `<4I` с полями `next, used, nonce, digest` и 128 байтов зашифрованных команд. За страницами находятся 32 зашифрованных байта целевого состояния. Длина файла: `120 + 48*144 = 7032` байта.

Страницы нужно обходить по цепочке `next`, начиная с номера `26`, а не по порядку в файле. Последняя ссылка равна `0xffffffff`. Состояние `ink` переносится между страницами, поэтому ошибка порядка ломает всё дальнейшее декодирование.

В коде узнаём xorshift32 со сдвигами `13,17,5`. Для физической страницы `physical` начальный ключ равен:

```python
key = ink ^ nonce ^ ((physical * 0x9e3779b9) & 0xffffffff)
```

Каждый из 128 байтов раскрывается с обратной связью по открытому байту:

```python
for j, enc in enumerate(encrypted_page):
    key = xs(key)
    b = enc ^ (key & 255)
    raw.append(b)
    key = (key + b + 17*j) & 0xffffffff
```

Правильность расшифровки проверяется FNV-1a по всем 128 байтам, включая неиспользованную часть последней страницы:

```python
h = 0x811c9dc5
for b in raw:
    h = ((h ^ b) * 0x01000193) & 0xffffffff
assert h == digest
```

Одна команда занимает восемь байтов `<4BI`: `op, d, s, r, k`. Но это ещё закодированные поля. Для глобального номера команды `ip` восстанавливаем их так:

```python
bank = (ip//16 + (ink & 3)) & 3
op = banks[bank][op]
d ^= (ink >> 8) & 15
s ^= (ink >> 12) & 15
r ^= (ink >> 16) & 31
k ^= rol32(ink, ip & 31)
```

Таким образом, один и тот же исходный значок в разных банках может означать разные операции. После страницы меняются чернила:

```python
ink = (rol32(ink ^ digest ^ nonce, 7) + 0x6d2b79f5) & 0xffffffff
```

После последней страницы ключ `ink ^ salt` раскрывает 32 байта цели обычным XOR с младшими байтами последовательных `xs(key)`, без обратной связи. Результат разбирается как `<8I`.

Теперь смотрим диспетчер VM. Она загружает весь флаг, включая обрамление, в `R0..R7` как восемь little-endian слов, а остальные регистры обнуляет. Все операции выполняются по модулю `2^32`:

| Код | Операция | Семантика |
| :--- | :--- | :--- |
| `0` | MOV | `R[d] = R[s]` |
| `1` | ADD | `R[d] += R[s]` |
| `2` | XOR | `R[d] ^= R[s]` |
| `3` | ROL | `R[d] = rol32(R[d], r)` |
| `4` | MULI | `R[d] *= k` |
| `5` | ADDI | `R[d] += k` |
| `6` | XORI | `R[d] ^= k` |
| `7` | SWAP | Обмен `R[d]` и `R[s]` |
| `8` | NOT | `R[d] ^= 0xffffffff` |
| `9` | BSWAP | Разворот четырёх байтов `R[d]` |
| `10` | LOADI | `R[d] = k` |
| `11` | SUB | `R[d] -= R[s]` |
| `12` | ROR | `R[d] = ror32(R[d], r)` |
| `13` | MULR | `R[d] *= R[s]` |
| `14` | NOP | Нет действия |
| `15` | HALT | Остановка |

Полный декодированный листинг можно получить командой из корня задания:

```sh
python solve/solve.py give/classroom.palm -v --dump vm.txt
```

В 754 командах замечаем повторяющиеся блоки из десяти инструкций:

```text
mov   R8, R[b]
rol   R8, rb
mov   R9, R[c]
muli  R9, odd
xor   R8, R9
addi  R8, key
xor   R8, R[src]
add   R[a], R8
rol   R[a], ra
xori  R[a], xkey
```

Здесь `a,b,c,src` — четыре различных индекса из `0..7`. Внутри раунда изменяется только один живой регистр `R[a]`; `R8,R9` служат временными. Поэтому блок сворачивается в формулу:

```python
F = (rol32(R[b], rb) ^ ((R[c] * odd) & MASK))
F = ((F + key) & MASK) ^ R[src]
R[a] = rol32((R[a] + F) & MASK, ra) ^ xkey
```

Для обращения не нужно восстанавливать прежние значения временных регистров. Остальные три живых регистра не изменились, значит, `F` можно вычислить из текущего состояния:

```python
R[a] = (ror32(R[a] ^ xkey, ra) - F) & MASK
```

Между раундами встречаются `SWAP`, `NOT` и `BSWAP` над живыми регистрами — каждая из этих операций обратна самой себе. Отдельные вычисления в `R12..R15` не влияют на `R0..R7`: солв проверяет, что они используют только эту отдельную группу регистров. Их можно исключить при обращении, но сохранить в прямом интерпретаторе для проверки.

В текущей выдаче получаются 64 обратимых раунда и всего 109 событий над живым состоянием. Начинаем с восьми целевых слов, обходим события в обратном порядке, обращаем раунды и выполняем остальные операции. Собираем результат через `struct.pack('<8I', *state)`.
