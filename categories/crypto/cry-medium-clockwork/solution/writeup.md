# Сломанный хронометр

| Событие | Название | Категория | Сложность |
| :-----: | :------: | :-------: | :-------: |
| VKACTF Kids 2026 | Сломанный хронометр | Crypto | Medium |

### Решение

В раздатке находятся исходники генератора и журнал из 32 диагностических слов. Генератор обновляет состояние по правилу `x_next = (a*x + b) mod p`, где `p = 2^127 − 1`. В журнал попадают только 47 старших бит состояния: младшие 80 бит отбрасываются. Записи сделаны с неизвестным постоянным интервалом от 2 до 61 шага, а пять позиций заменены случайными значениями.

Флаг хранится в контейнере `box`. Для его открытия нужно восстановить начальное состояние и интервал записи. Это задача восстановления по усечённым модульным наблюдениям: используем **решёточную атаку с LLL**, а повреждённые записи обходим перебором небольших подмножеств.

**Принцип атаки**

Для предполагаемого интервала `s` состояние в записи с номером `i`, начиная с единицы, выражается через исходное состояние `x`:

```text
A_i = a^(i*s) mod p
B_i = b * (A_i − 1) * (a − 1)^(-1) mod p
x_i = (A_i*x + B_i) mod p
```

Положим `W = 2^80`. Если диагностическое слово `y_i` не повреждено, то `x_i` находится в интервале `[y_i*W, (y_i+1)*W)`. Вычитая известное смещение `B_i`, получаем приближённое модульное равенство:

```text
t_i = (y_i*W + W/2 − B_i) mod p
A_i*x − q_i*p ≈ t_i
```

Ошибка этого приближения по абсолютной величине не превышает `W/2`. Вместо перебора младших 80 бит ищем короткий вектор решётки, который одновременно объясняет несколько наблюдений.

**Построение решётки**

Берём восемь записей и строим десятимерный базис. Первые восемь координат соответствуют наблюдениям, девятая — состоянию, десятая — дополнительной координате для сведения приближённой системы к поиску короткого вектора:

```text
(p²,  0, ...,  0, 0,   0)
( 0, p², ...,  0, 0,   0)
                 ...
( 0,  0, ..., p², 0,   0)
(p*A_1, ..., p*A_8, W,   0)
(p*t_1, ..., p*t_8, 0, p*W)
```

Из последней строки вычитаем `x` экземпляров предпоследней и добавляем подходящие кратные первых восьми строк. Для правильного состояния первые координаты становятся малыми ошибками, девятая равна `−W*x`, а последняя — `p*W`. Состояние можно выбирать в симметричном диапазоне по модулю `p`, чтобы девятая координата также оставалась небольшой.

Применяем LLL и рассматриваем строки, у которых последняя координата равна `±p*W`, а предпоследняя делится на `W`. Из такой строки извлекаем кандидата:

```python
if abs(v[-1]) == p * W and v[-2] % W == 0:
    sign = 1 if v[-1] > 0 else -1
    initial = (-v[-2] // W * sign) % p
```

**Обработка повреждённых записей**

Одна восьмёрка может содержать ложное наблюдение, поэтому солвер проверяет четыре последовательных блока и ещё 28 воспроизводимо выбранных подмножеств. Seed выбора подмножеств определяет только порядок поиска и не связан с приватным seed задачи.

Для каждого интервала и подмножества:

1. Вычисляем коэффициенты `A_i`, `B_i` и центры интервалов `t_i`.
2. Строим базис, применяем LLL и извлекаем кандидатов на начальное состояние.
3. Проверяем кандидата по всем 32 словам: должны совпасть не менее 27.
4. Передаём `[initial, stride]` в публичную функцию `unseal` из `core.py`.

`unseal` проверяет MAC контейнера и при совпадении расшифровывает флаг. Проверка по всему журналу отсеивает ложные короткие векторы, а MAC подтверждает окончательный ответ. LLL и выбор подмножеств здесь эвристические; для предоставленного экземпляра решение проверено.

**Запуск решения**

Для запуска нужны Python 3.10+ и `python-flint==0.8.0` из [requirements.txt](requirements.txt). Команда из корня набора:

```sh
python3 01_clockwork/solution/solve.py
```

Скрипт читает соседний каталог `give`; другой путь к раздатке можно передать первым аргументом. Сервер и интернет во время решения не требуются.

Солв представлен в файле [solve.py](solve.py).
